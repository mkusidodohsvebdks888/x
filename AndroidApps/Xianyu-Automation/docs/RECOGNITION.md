# 买家、会话、商品与消息识别规则

## 1. 页面分类

ScreenClassifier 输出：

- CHAT_LIST：聊天会话列表。
- CHAT_DETAIL：单个聊天详情。
- PRODUCT_CARD_VISIBLE：当前页面存在可识别商品卡片。
- OTHER：闲鱼其他页面。
- UNKNOWN：证据不足，无法分类。

分类依据为包名、可见节点文字、控件 ID、节点结构和屏幕区域的组合。不得依赖单一易变文案。

## 2. 买家识别

优先级：

1. 页面明确暴露的平台买家 ID。
2. 当前聊天页面明确显示的买家资料线索。
3. 仅有昵称时，创建本地 UUID 并标记 unverified。

昵称不能作为唯一键；同昵称的不同会话不能自动合并。头像或显示名称变化也不能证明身份变化或相同。

## 3. 会话识别

平台会话 ID 仅在页面明确提供时记录。若没有：

- 建立本地 conversation UUID。
- 记录观察时间、页面类型和可见买家线索。
- 不声称该本地 ID 是平台会话 ID。
- 不保证退出 APP 或跨设备后仍能稳定识别同一会话。

## 4. 商品卡片识别

字段提取优先级：

1. 页面明确显示的商品 ID。
2. 商品卡片标题。
3. 商品价格文本。
4. 页面提供的图片描述或其他可见属性。

匹配策略：

- 有明确商品 ID 且与本地商品记录一致：可建立高等级候选。
- 无商品 ID：标题和价格用于生成候选，不直接证明唯一商品。
- 多个商品标题相同或价格相近：标记 pending_confirmation。
- 未显示商品卡片：不从聊天内容猜测商品。
- 商品卡片无法访问：标记 unknown。

## 5. 会话与商品绑定证据

evidence_level：

- explicit_id：页面明确提供商品 ID。
- visible_card：当前聊天页面显示商品卡片，但缺少可验证 ID。
- local_match：与本地商品库匹配，仅作候选。
- manual：用户在本地 APP 中确认。

绑定状态：

- confirmed：有明确证据或用户确认。
- pending_confirmation：存在候选但不足以自动确认。
- rejected：用户明确否定该关联。
- unknown：没有足够线索。

## 6. 消息解析

每条可见消息尝试提取：

- 正文或可读摘要
- 消息方向：buyer / seller / unknown
- 消息类型：text / image / system / unknown
- 可见时间线索
- 所属本地会话

消息方向必须基于节点结构、控件属性和布局证据判断。仅靠气泡左右位置不能作为跨版本通用的唯一判断条件。

## 7. 意图分类（本地规则）

| 类别 | 示例关键词 / 线索 |
|---|---|
| PRICE | 价格、多少钱、最低、便宜 |
| PRODUCT_DETAIL | 规格、尺寸、成色、型号、功能 |
| STOCK | 库存、还有吗、有货吗 |
| LOGISTICS | 发货、快递、物流、什么时候到 |
| AFTER_SALES | 使用、故障、售后、退款 |
| TRANSACTION | 订单、付款、已支付等明确交易文案 |
| OTHER | 其他可读消息 |
| UNKNOWN | 文本不足或规则冲突 |

规则匹配只用于辅助分类，不触发任何回复或交易动作。多个意图同时命中时保留多标签或标记 UNKNOWN，不强行选择。

## 8. 识别结果必须可解释

每个关键字段记录：
- 原始来源类型（Accessibility 节点 / 用户确认）
- 观察时间
- 证据等级
- 是否经过人工确认

不得生成没有证据支持的平台 ID、商品 ID 或精确置信度。
